# Recheck Mord

Google Apps Script для автоматичного перенесення проєктів з основних місячних листів «Морда» до гарантійного перечеку.

Канонічний файл скрипта в цьому репозиторії — [`Code.gs`](Code.gs).

## Що робить скрипт

Під час щоденного запуску скрипт:

1. переглядає всі видимі листи, назва яких починається з `Морда`;
2. відбирає рядки зі статусом `Прийнято` або `Перевірено`, коректним дедлайном, номером без цифрового суфікса `/1`, `/2` тощо та посиланням у `ТЗ замовника`;
3. починаючи з дати `Дедлайн + 14 днів`, копіює рядок у лист `Перечек по гарантії - <місяць дедлайну>`;
4. встановлює `Перевірка = Потрібно зробити заміни`;
5. встановлює `End data = Дедлайн + 21 день`;
6. не видаляє і не змінює вихідний рядок у «Морді»;
7. записує результат у прихований лист `_Warranty log`.

Якщо потрібного гарантійного листа немає, скрипт створює його з наявного гарантійного листа-шаблону, зберігає структуру й оформлення та очищує дані нижче заголовків.

## Чого скрипт не робить

Цей код не перевіряє донорів, не рахує втрати, не видає Telegram-завдання, не керує колами замін і не переносить клієнтський звіт. Це функції окремої системи `work-checker`.

У `Code.gs` є резервний ручний сценарій: якщо відповідальна людина вручну змінить одну клітинку `Перевірка` гарантійного рядка на `Перечек готово`, встановлений `onEdit`-тригер оформить дати в робочому ТЗ та синхронізує статус у «Морді». Цей сценарій не є повною заміною фіналізації через `work-checker`.

## Швидкий старт

> **Увага:** `WR_runDailyTransfer_v1` не має режиму попереднього перегляду. Ручний запуск одразу обробляє всі придатні рядки у всіх видимих листах «Морда».

1. Відкрийте потрібну майстер-таблицю Google Sheets.
2. Перейдіть до **Розширення → Apps Script**.
3. Створіть один файл `Code.gs` і вставте в нього вміст репозиторного [`Code.gs`](Code.gs).
4. Не залишайте в Apps Script іншу копію цих самих функцій.
5. Збережіть проєкт і запустіть `WR_setupWarrantyAutomation_v1`.
6. Надайте запитані дозволи.
7. Перевірте, що створено два тригери:
   - `WR_runDailyTransfer_v1` — щоденний часовий тригер;
   - `WR_installedOnEdit_v1` — тригер редагування таблиці.
8. Перевірте часові пояси таблиці та Apps Script, доступ до майстер-таблиці й робочих ТЗ.

Повна покрокова інструкція: [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md).

Технічна логіка, контракти даних і обмеження: [`docs/TECHNICAL_GUIDE.md`](docs/TECHNICAL_GUIDE.md).

Правила внесення змін і публікації: [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Мінімальні вимоги до таблиці

Заголовки розміщуються в першому рядку.

| Заголовок | Де потрібен | Призначення |
| --- | --- | --- |
| `ТЗ замовника` | «Морда» і гарантійний лист | Посилання на робоче ТЗ та ключ для пошуку повторів |
| `Перевірка` | «Морда» і гарантійний лист | Вхідний і фінальний статус |
| `Дедлайн` або `Deadline` | «Морда» | Дата переносу, цільовий місяць і `End data` |
| `№`, `No` або `Номер` | «Морда» | Номер проєкту |
| `№`, `No`, `Номер` або `l` | гарантійний лист | Номер проєкту |
| `Коментар Аня` | «Морда» і гарантійний лист | Коментар, який переноситься окремо |
| `End data` або `End date` | гарантійний лист | Кінцевий строк замін |

Для резервного ручного завершення на першому листі робочого ТЗ мають бути заголовки `Donor` і `Text` або `Date` в одному з перших десяти рядків.
